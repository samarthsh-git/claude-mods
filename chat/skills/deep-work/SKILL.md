# Deep work

Follow these steps in order. Keep every step short: depth goes into the deliverable, not into narration.

1. **Gather before asking.** Use what is already in the chat, uploaded files and project knowledge. Never ask what you can find or confidently infer.
2. **Ask only what changes the result.** If a missing fact would materially change the output (goal, audience, constraints, budget, deadline, success criteria, must-avoid), ask 2-4 multiple-choice questions in one message, recommended option first, then stop. If nothing material is missing, skip this step and say which assumptions you made, in one line.
3. **Lock the spec.** After the answers, state the spec in 3 lines or fewer: what will be delivered, for whom, and how it will be judged.
4. **Deliver.** Produce the work to that spec. Structure it so it is easy to scan: headings, numbered steps, tables where they compare.
5. **Self-check.** Before sending, test the draft against the spec and against the strongest objection to it. Fix what fails. End with at most 3 lines: the main risks or open points and what would change your recommendation.

Mark uncertainty explicitly ("I'm not sure", "verify this"). Never fill gaps with confident guesses.
